# Основное решение

## Ограниченные контексты

1. Синхронизация данных с агентами
2. Маршрутизация запросов, аутентификация и балансировка
3. Обработка телеметрии и мониторинг состояния техники
4. Управление сельскохозяйственными процессами
5. Хранение исходных данных
6. Хранение агрегированных данных

## Подходы, технологии и компромиссы

|**№**|**Подход / Технология**|**Преимущества**|**Недостатки**|
| :-: | :- | :- | :- |
| 01 | Истользование PostgreSQL для хранения агрегированных данных | Надежность и целостность данных; Расширяемость; Поддержка разных типов данных; Безопасность; Открытый исходный код | Порог входа и настройка; Сложность горизонтального масштабирования |
| 02 | Использование существующей BI-системы | Минимизация затрат на переработку отчетов | сохраняется зависимость от вендора |
| 03 | Использование центрального сервера | Проще разработка, более быстрая поставка рабочего решения | Сложнее горизонтальное масштабирование |
| 04 | Использование Nginx как API GateWay | Высокая скорость; Экономия памяти; Многофункциональность; Надежность| Сложность настройки; Хуже справляется с динамическим контентом |
| 05 | Использование RabbitMQ* для передачи данных от агентов к центральном серверу | Гарантированная доставка данных | Сложность настройки |

*В дальнейших схемах MSA-Agro использование RabbitMQ не отображается для упрощения схем.

## Подходы, технологии и компромиссы

|**№**|**Подход / Технология**|**Преимущества**|**Недостатки**|
| :-: | :- | :- | :- |
| 01 | Использование GoLang для создания микросервисов | Высокая скорость; простой синтаксис; Удобная многопоточность; Мощная стандартная библиотка; Единый стандарт кода | Многословная обработка ошибок; Отсутствие ООП; Слабая гибкость интерфейсов |
| 02 | Функционал формирования отчетов переносится в Облачную платформу | Возможность формирования отчетов без использования дополнительного ПО | Экономия на лицензиях BI; Дополнительные трудозатраты в разработке; Возможность тиражирования на другие организации |
| 03 | Использование облачной платформы | Возможность дальнейшего развития решения в SaaS платформу | Более высокая сложночть разработки |
| 04 | Использование Kafka как событийной шины | Высокая пропускная способность; Отказоустойчивость и надежность; Хранение истории сообщений; Горизонтальное масштабирование; Независимость потребителей | Сложность поддержки и настройки; Отсутствие сложной маршрутизации; Избыточность для простых задач; Повышенная задержка (Latency) в некоторых сценариях |
| 05 | Использование Nginx как API GateWay | Высокая скорость; Экономия памяти; Многофункциональность; Надежность| Сложность настройки; Хуже справляется с динамическим контентом |
| 06 | Использование RabbitMQ** для передачи данных от агентов к центральном серверу | Гарантированная доставка данных | Сложность настройки |

**В дальнейших схемах MSA-Agro использование RabbitMQ не отображается для упрощения схем.
